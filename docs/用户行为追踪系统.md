# 用户行为追踪系统

## 概述

用户行为追踪系统记录从用户请求到 Agent 执行的完整链路，帮助你：
- 📊 了解系统使用情况
- 🐛 调试和排查问题
- 📈 分析性能瓶颈
- 🔍 追踪工具使用情况

## 架构

```
用户请求
    ↓
UserAction (用户行为)
    ├─ action_id: 唯一标识
    ├─ action_type: 行为类型（generate_lesson, chat, etc.）
    ├─ request_data: 请求数据
    └─ timestamp: 时间戳
    ↓
AgentExecution (Agent 执行)
    ├─ execution_id: 执行标识
    ├─ agent_name: Agent 名称
    ├─ input_data: 输入数据
    ├─ output_data: 输出数据
    ├─ elapsed_ms: 执行时间
    └─ status: 执行状态
    ↓
ToolExecution (工具执行)
    ├─ tool_execution_id: 工具执行标识
    ├─ tool_name: 工具名称
    ├─ params: 参数
    ├─ result: 结果
    ├─ elapsed_ms: 执行时间
    ├─ degraded: 是否降级
    └─ status: 执行状态
    ↓
ActionTrace (完整追踪链路)
    ├─ action: 用户行为
    ├─ agents: Agent 执行列表
    ├─ tools: 工具执行列表
    ├─ total_elapsed_ms: 总耗时
    └─ final_status: 最终状态
```

## 自动追踪

系统已自动集成到 `LessonOrchestrator`，无需额外配置：

```python
# 在 orchestrator.run() 中自动追踪
result = orchestrator.run(
    topic="量子计算",
    template_category="comprehensive",
    conversation_state=state,
)

# 追踪记录自动写入 logs/user_action_traces.jsonl
```

## 追踪内容

### 1. 用户行为 (UserAction)
- **action_id**: 唯一标识符
- **action_type**: 行为类型
  - `generate_lesson`: 生成教案
  - `chat`: 对话
  - `feedback`: 反馈
- **request_data**: 请求数据
  - topic: 主题
  - template_category: 模板类别
- **session_id**: 会话 ID
- **timestamp**: 时间戳

### 2. Agent 执行 (AgentExecution)
- **execution_id**: 执行标识
- **agent_name**: Agent 名称
  - PlannerAgent
  - QueryAgent
  - RetrieverAgent
  - WriterReviewerAgent
- **input_data**: 输入数据
- **output_data**: 输出数据
- **elapsed_ms**: 执行时间（毫秒）
- **status**: 执行状态
  - started: 开始
  - completed: 完成
  - failed: 失败

### 3. 工具执行 (ToolExecution)
- **tool_name**: 工具名称
  - web_search
  - image_retrieval
  - latex_renderer
- **params**: 工具参数
- **result**: 执行结果
- **elapsed_ms**: 执行时间（毫秒）
- **degraded**: 是否降级（工具失败但不影响主流程）
- **status**: 执行状态

## 查看追踪记录

### 方式 1：使用查看工具

```bash
# 查看最近 10 条记录
.venv/bin/python scripts/view_user_actions.py

# 查看最近 20 条记录
.venv/bin/python scripts/view_user_actions.py --limit 20

# 只查看统计信息
.venv/bin/python scripts/view_user_actions.py --stats

# 查看特定 action_id 的记录
.venv/bin/python scripts/view_user_actions.py --action-id abc123
```

### 方式 2：直接读取日志文件

```bash
# 查看原始 JSON 记录
cat logs/user_action_traces.jsonl

# 使用 jq 格式化查看
cat logs/user_action_traces.jsonl | jq .

# 查看最后一条记录
tail -n 1 logs/user_action_traces.jsonl | jq .
```

### 方式 3：编程方式

```python
from src.observability.user_action_tracker import get_tracker

# 获取追踪器
tracker = get_tracker()

# 获取统计信息
stats = tracker.get_statistics(limit=100)
print(f"总行为数: {stats['total_actions']}")
print(f"平均耗时: {stats['avg_elapsed_ms']:.1f}ms")
print(f"Agent 使用: {stats['agent_usage']}")
print(f"工具使用: {stats['tool_usage']}")
```

## 性能影响

追踪系统设计为低开销：
- ✅ 异步写入，不阻塞主流程
- ✅ 内存占用小（完成后立即清理）
- ✅ 文件追加写入，性能高
- ✅ 可选功能，可随时禁用

## 使用场景

### 1. 调试问题

```bash
# 查看最近失败的请求
cat logs/user_action_traces.jsonl | jq 'select(.final_status == "failed")'

# 查看特定 session 的所有请求
cat logs/user_action_traces.jsonl | jq 'select(.action.session_id == "session_123")'
```

### 2. 性能分析

```bash
# 查看耗时最长的请求
cat logs/user_action_traces.jsonl | jq -s 'sort_by(.total_elapsed_ms) | reverse | .[0:10]'

# 查看工具执行时间
cat logs/user_action_traces.jsonl | jq '.tools[] | {tool_name, elapsed_ms}'
```

### 3. 使用统计

```bash
# 统计工具使用次数
cat logs/user_action_traces.jsonl | jq '.tools[].tool_name' | sort | uniq -c

# 统计降级次数
cat logs/user_action_traces.jsonl | jq '.tools[] | select(.degraded == true)' | wc -l
```

## 扩展追踪

### 添加自定义追踪

```python
from src.observability.user_action_tracker import get_tracker

# 获取追踪器
tracker = get_tracker()

# 开始追踪自定义行为
action_id = tracker.start_action(
    action_type="custom_action",
    request_data={"param1": "value1"},
    user_id="user_123",
    session_id="session_456",
)

# 追踪自定义 Agent
execution_id = tracker.start_agent(
    action_id=action_id,
    agent_name="CustomAgent",
    input_data={"input": "data"},
)

# 完成 Agent 追踪
tracker.complete_agent(
    action_id=action_id,
    execution_id=execution_id,
    output_data={"output": "result"},
    status="completed",
)

# 完成行为追踪
tracker.complete_action(action_id=action_id, final_status="completed")
```

### 添加自定义工具追踪

```python
# 在工具执行后记录
tracker.record_tool(
    action_id=action_id,
    execution_id=execution_id,
    tool_name="my_custom_tool",
    params={"param": "value"},
    result={"result": "data"},
    elapsed_ms=123.4,
    status="completed",
    degraded=False,
)
```

## 数据保留

- 追踪记录默认保存在 `logs/user_action_traces.jsonl`
- 文件会持续增长，建议定期归档
- 可以使用 logrotate 或类似工具自动轮转

```bash
# 归档旧记录
mv logs/user_action_traces.jsonl logs/user_action_traces_$(date +%Y%m%d).jsonl

# 压缩归档
gzip logs/user_action_traces_*.jsonl
```

## 隐私和安全

- ⚠️ 追踪记录可能包含敏感信息（用户输入、主题等）
- 建议在生产环境中：
  - 定期清理或归档日志
  - 限制日志文件访问权限
  - 考虑脱敏处理敏感数据

## 故障排查

### 问题 1：追踪文件不存在

**原因**：还没有执行过任何请求

**解决**：运行一次教案生成，系统会自动创建追踪文件

### 问题 2：追踪记录不完整

**原因**：程序异常退出，未完成追踪

**解决**：检查程序日志，确保正常完成

### 问题 3：追踪文件过大

**原因**：长时间运行积累了大量记录

**解决**：定期归档或清理旧记录
